# Sanuvia Review Harness

A lightweight, cloud-hostable, mobile-responsive **engineering diagnostic tool**
for validating the Persistent Reasoning Core (Phase 0) in isolation.

## Purpose

The reasoning engine is the product under test. The review harness exists solely
to let the engineering and design team **drive the engine with structured
evidence, inspect everything it produces, and run the acceptance proof** — from a
browser, on desktop or phone.

The authoritative input is a **canonical, structured `EvidenceRecord`**, not
free-text conversation. The harness does **no** natural-language understanding and
**no** evidence extraction — it does not test those, and must never grow into the
Phase 1 conversation experience. It sits entirely *above* the existing API and
contains no reasoning:

```
Browser  →  HTTP adapter  →  Application API  →  Reasoning Engine  →  Persistence
                                (ReasoningService /        (unchanged, frozen core)
                                 WorldModelView)
```

## Test Cases

Work is organised into **Test Cases**. A Test Case is **one deterministic
reasoning experiment**: an ordered sequence of `EvidenceRecord`s plus the
reasoning state produced by running them. Each Test Case is fully isolated (its
own store), holds its own reasoning history, and contains:

- ordered EvidenceRecords, immutable WorldModel versions, the RevisionLedger,
- hypotheses, predictions, inquiries, provenance, and recognition data.

The **Test Cases** selector switches the active experiment and refreshes every
panel from it. **New Test Case**, **Duplicate**, and **Save** manage them. (With
`SANUVIA_TESTCASE_DIR` set, saved definitions persist across restarts; only the
authored sequence is saved — the reasoning state is regenerated by rerunning,
deterministically.)

## The workflow

1. **Create** a Test Case (or select an existing one).
2. **Add** structured `EvidenceRecord`s one at a time (they queue in the
   sequence, not yet run).
3. **Run Next Step** to run one item, or **Add & Run** to add-then-run.
4. **Run Full Sequence** to reset and run everything (deterministic rerun).
5. **Inspect** the engine's output after every step (all panels below).
6. **Reset** to clear reasoning state while keeping the sequence, then rerun.
7. **Duplicate** a Test Case to branch an experiment.
8. **Save** a Test Case definition.

## The canonical EvidenceRecord form

Every submission authors a complete structured `EvidenceRecord` — no JSON typing:

| Field | Notes |
| --- | --- |
| Evidence ID | auto-generated (`evidence-N`) |
| Subject ID | the Test Case's subject (auto) |
| Timestamp / sequence position | auto, deterministic |
| Observed content | the structured `RawObservation` |
| Evidence class | Narrative / Reflective / Behavioural / Contradictory / Missing / Failed Acquisition |
| Source | provenance source |
| Evidence reliability | `0–1` |
| Classification confidence | `0–1` |
| Provenance confidence | `0–1` |
| Classification status | e.g. `provisional` (carried in metadata) |
| Metadata | `key=value` lines |
| Structured appraisal | Supports / Contradicts (hypothesis ids) and Proposals (`id \| statement \| support`) — reviewer-authored, **not** extracted |

Because Phase 0 has no foundation model, the *appraisal* (which hypotheses the
evidence bears on, and any new candidate explanations) is supplied by the
reviewer and relayed to the engine through the existing appraiser port. The
engine performs all reasoning.

## Inspect the reasoning

Every panel is populated directly from the engine's output for the current Test
Case: Evidence Sequence, Evidence (recorded), Current World Model, Active
Hypotheses + support, Predictions, Inquiry, Revision Events, Revision Ledger,
Model Uncertainty (before → after), Provenance, and Recognition Conditions
(deferred in Phase 0, so normally empty).

## Trace, graph, exit test

- **Reasoning Trace** and **Reasoning Lineage Graph** render **the current Test
  Case** (via the refactored, pure `reasoning_trace` / `reasoning_graph`
  renderers). A **Reference** button renders the canonical exit-test scenario.
- **Run Exit Test** executes `sanuvia.exit_test.run()` verbatim: PASS/FAIL plus
  each check. Its status is recorded against the current Test Case.

All three read only the engine's own state — one source of truth. If the engine
changes, these outputs change automatically.

## Reviewer tools

- **Sample library** — a curated catalogue of static engineering Test Cases
  (Relationship Distance, Contradictory Evidence, Failed Acquisition, Competing
  Hypotheses, Trust Recovery, Mixed Signals, Anxiety vs Avoidance, Reassurance
  Seeking, Escalation (model holds), Prediction Revision). These are **not**
  engine-generated. Load one with a click — it becomes a new editable Test Case;
  the originals are never modified. Then duplicate, modify, save, or run it.
- **Import / Export** — Export the current Test Case (JSON), the Reasoning Trace
  (Markdown), the Lineage Graph (Mermaid `.mmd` and Graphviz `.dot`), or a
  complete **Review Report** (Markdown). Import a Test Case (JSON), which becomes
  a normal editable Test Case.
- **Engineering Summary** — a compact panel above the details: Test Case name,
  EvidenceRecords, interactions executed, WorldModel versions, revision events,
  active hypotheses, predictions, inquiries, current model uncertainty, exit-test
  status, deterministic flag, backend, and engine version.
- **Step Timeline** — every interaction as a step (evidence → hypotheses created
  → WorldModel version → inquiry → predictions → uncertainty before/after).
  Selecting a step refreshes every panel to that point in history. It is a
  visualization over the stored per-step snapshots — no reasoning is re-run.
- **Review Report** — one downloadable Markdown report: Test Case info, evidence
  sequence, reasoning trace, lineage graph, revision ledger, current world model,
  hypotheses, predictions, inquiries, uncertainty timeline, exit-test results and
  pass/fail summary, timestamp, engine version, and backend.
- **Reviewer Notes & Tags** — attach free-text notes and categorisation tags to a
  Test Case. These are **review metadata only** — never sent into the engine —
  and are saved/loaded with the Test Case definition.
- **Comparison Mode** — pick two Test Cases and diff their evidence, hypotheses,
  predictions, revision count, model uncertainty, and exit-test status — for
  regression review.
- **Search** — across saved/open Test Cases by name, evidence text, hypothesis,
  tags, or creation date, with an optional tag filter.

## Run locally

```bash
pip install -e ".[dev]"
python -m sanuvia.adapters.http.server
# open http://localhost:8000
```

Environment variables (all optional):

| Var | Default | Meaning |
| --- | --- | --- |
| `SANUVIA_HOST` | `0.0.0.0` | bind host |
| `SANUVIA_PORT` | `8000` | port |
| `SANUVIA_BACKEND` | `memory` | `memory` or `sqlite` (durable reasoning stores) |
| `SANUVIA_DB_PATH` | `/data/sanuvia.db` | SQLite base path (when backend=sqlite) |
| `SANUVIA_TESTCASE_DIR` | unset | directory for saved Test Case definitions (durable); unset = in-memory |

## Deploy

```bash
docker compose up            # builds the image and starts the harness
# open http://localhost:8000
```

Standard-library only (the core has zero runtime dependencies), so it runs
anywhere Docker runs — no cloud-vendor assumptions. A named volume persists
`/data` (SQLite databases and saved Test Cases). `ThreadingHTTPServer` is
sufficient for an internal review tool; for higher concurrency place it behind a
reverse proxy.

## What "review" confirms

A reviewer can build a Test Case from structured `EvidenceRecord`s, run it step by
step or all at once, watch the WorldModel version advance, confirm hypotheses
compete and revise, see uncertainty rise and fall, read the inquiry, open the
trace and graph for that Test Case, run the exit test, duplicate and save the
experiment, and confirm **every displayed artifact comes directly from the
engine** — validating the Persistent Reasoning Core remotely without it ever
becoming the Phase 1 product.
